## Context

The Docusaurus site models each module as a typed `Module` object (`src/data/ciudadbots/types.ts`) rendered by one shared `<Module id="mX" />` component, plus an autogenerated sidebar (`sidebars.ts` → one doc per `docs/NN-slug.mdx` file). This structure works well and should not change.

The gap is that the original HTML computed a lot of *shared, grade-level content* on the fly inside JS functions — `basicoAlignment()`, `internationalAlignment()`, `cnbAchievementIndicators(m)` — rather than storing it per module. `cnbAchievementIndicators(m)` in particular is almost entirely generic text with only `m.title` substituted in; duplicating that verbatim into all 12 modules' data would be a maintenance trap (12 copies to keep in sync). The design goal is to port the *content*, not the *duplication pattern*.

## Goals / Non-Goals

**Goals:**
- Reproduce every distinct piece of teacher-facing content from the HTML source, including the showcase page and the grade-differentiated CNB/standards depth, without losing wording.
- Store grade-level/standards content once (shared dataset), parameterized by module title where the original did the same, so 12 modules don't carry 12 near-identical copies.
- Keep the existing `Module` component contract stable (same tabs, same props) — this is additive depth inside the existing "CNB y estándares" tab, not a redesign.
- Add the showcase page as a normal doc page, consistent with how the other 12 modules are added (`docs/NN-*.mdx` + autogenerated sidebar).

**Non-Goals:**
- No redesign of navigation, tabs, or the module data shape beyond what's needed to carry the new shared content.
- No change to `BuildGuide`, `ProgressTracker`, or `CityBotsHero` behavior.
- No decision here to resurrect the `original` (dead local-path) links — those stay dropped, as already decided in the prior sync.

## Decisions

### Decision 1: Shared grade-level content lives in one new data module, not per-Module fields
**Choice**: Add `src/data/ciudadbots/standards.ts` (or similar) exporting the static, non-module-specific content: `basicoAlignment` (3 level descriptions + the 4-row comparison table), `internationalAlignment` (ISTE/CSTA/NGSS progression tables, cards, and source links), and a template function `achievementIndicators(moduleTitle: string)` that reproduces `cnbAchievementIndicators(m)`'s per-grade rows with the title substituted in.

**Rationale**: This mirrors the original's own structure (shared JS functions called with `m` as a parameter) and avoids 12x duplication of near-identical paragraphs, which would drift over time.

**Alternative considered**: Add the fields directly to each of the 12 module objects — rejected as pure duplication of text that isn't actually module-specific in the source.

### Decision 2: New presentational components, reused across the Module CNB tab and the showcase page
**Choice**: Add `AchievementIndicators`, `StandardsProgression` (renders `basicoAlignment` + `internationalAlignment`), and reuse the existing rubric-table pattern from `Module`'s eval tab for the showcase page's final rubric (extract a small shared `RubricTable` if the markup is identical, otherwise duplicate the ~20 lines rather than over-abstracting).

**Rationale**: `internationalAlignment()` in the HTML is invoked twice (once per module, once on the overview page) with identical output — a component avoids copy-pasting the same JSX/markup twice in this port too.

**Alternative considered**: Inline everything into MDX per page — rejected, MDX is a poor fit for tables generated from data (12 modules × repeated tables).

### Decision 3: Showcase is a doc page, not a custom React page
**Choice**: `docs/13-showcase.mdx` with `sidebar_position: 13`, following the exact pattern of `docs/01-trazamapas-chapin.mdx` through `docs/12-*.mdx`. Its rubric and phase content render via a small `<Showcase />` component (analogous to `<Module id="m1" />`) so the sidebar autogeneration in `sidebars.ts` picks it up with zero config changes.

**Rationale**: Consistency — every other session is a doc page; the showcase is conceptually "session 13" in the original nav (`showSes('showcase')` sat right after the 12 modules).

**Alternative considered**: A dedicated `src/pages/showcase.tsx` like `estudiante` — rejected, `estudiante` is a special stripped share-view for students, but showcase is a normal teacher-guide session and belongs in the same docs flow as the other 12.

### Decision 4: Overview page restoration happens in MDX + the same shared components from Decision 2
**Choice**: Expand `docs/overview.mdx` to include the pacing/scope-list (as a plain MDX list or a small `<ScopeOptions>` component if a visual grid is wanted), the full `<StandardsProgression>` block (same component as module pages, so it isn't hand-copied a third time), and a plain-MDX module index list linking to each of the 13 docs pages (12 modules + showcase).

**Rationale**: Keeps the overview page's existing MDX-first structure (per current file) rather than converting it to a fully componentized page.

### Decision 5: `trazamapas-chapin-guia-construccion.pdf` gets an explicit link, not a silent drop
**Choice**: Add a "descargar guía en PDF" secondary link to the `BuildGuide` resource card (or its containing resource card in `Module`'s Recursos tab) pointing at the copied static asset. Copy the PDF into `static/assets/ciudadbots/` alongside the build-guide images if not already reachable there.

**Rationale**: The proposal calls for an explicit decision rather than a silent gap; a PDF fallback is low-cost and matches the original's intent of having a downloadable/reference document behind the page-by-page viewer.

**Alternative considered**: Deliberately drop it since the image viewer supersedes it — rejected because the original explicitly kept a `pdf` behind the viewer and a downloadable original is still useful to teachers without a live viewer.

## Risks / Trade-offs

| Risk | Mitigation |
|------|-----------|
| Grade-level content (`basicoAlignment`, `internationalAlignment`) is long, dense Spanish prose — easy to introduce transcription errors | Extract by direct copy from HTML lines 636–649 and 607–634, diffed against the new TSX output before commit |
| New shared components increase surface area of `src/data/ciudadbots/` and `src/components/` | Keep components presentational/props-only (no new state), matching existing `Module`/`BuildGuide` conventions |
| Showcase page rubric duplicates ~20 lines of table markup already in `Module`'s eval tab | Acceptable duplication per Decision 2 unless a shared `RubricTable` proves trivial once both are written side by side |
| Sidebar autogeneration ordering could shift if `sidebar_position` values collide | Use `13` for showcase, leaving room below existing `1`–`12`; verify rendered sidebar order in dev server before considering this done |

## Migration Plan

1. Add shared data module (`standards.ts`) with `basicoAlignment`, `internationalAlignment`, `achievementIndicators()`.
2. Build `StandardsProgression` and `AchievementIndicators` components; wire into `Module`'s CNB tab (per module).
3. Build `Showcase`/`RubricTable` content and `docs/13-showcase.mdx`; verify sidebar picks it up.
4. Expand `docs/overview.mdx` with scope-list, `StandardsProgression`, básico breakdown, and full session index.
5. Resolve the PDF asset link.
6. Manual verification pass: dev server, click through all 12 modules + overview + showcase, compare against the original HTML section by section.
