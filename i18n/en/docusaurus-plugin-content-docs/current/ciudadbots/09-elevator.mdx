# 09 · Elevator

:::note For the teacher
Review the **Implementation** tab first (phases and concepts), prepare the **Resources** (base
program and guide), then close out planning with **CNB & Standards** and **Evaluation**. You can
rotate team roles — Builder, Organizer, Programmer — throughout the module.
:::

<Module id="m9">
  <Module.Question>
    How does an elevator know where it is, where it needs to go, and when to safely open its
    doors?
  </Module.Question>

  <Module.Context>
    This module introduces stateful systems through a GuateGeeks elevator for buildings, malls, or
    school libraries: variables for current floor, selected floor, maximum floors, doors, and a
    sensor for the initial reference point.
  </Module.Context>

  <Module.Concepts items={[
    "Variables",
    "Events and messages",
    "Current state vs. destination",
    "Safety doors",
    "Initial floor calibration",
  ]} />

  <Module.Phase kind="act" label="Activate · 15 min" title="Real elevators">
    Ask what an elevator does before it moves: close doors, know the current floor, and validate the
    destination. Each team draws a simple table with current floor, requested floor, and door state.
    Initial evidence: one safety rule that states when the elevator may move and when it may open.
  </Module.Phase>

  <Module.Phase kind="exp" label="Explore · 30 min" title="A system with memory">
    Identify the winch, doors, force sensor, and display. Introduce variables for selected floor,
    current floor, and maximum floor; then test moving up and down without a payload and with hands
    away from doors, rope, and winch. Checkpoint: the team calibrates the initial floor and explains
    which variable must change before, during, and after movement.
  </Module.Phase>

  <Module.Phase kind="cre" label="Create · 120 min" title="Select and move between floors">
    Build the Elevator and program button selection, floor display, calculated movement, and
    door opening/closing. Run test cases: same floor, one floor up, several floors, and invalid
    destination if applicable. Record current floor, destination, direction, distance moved, and door
    state. If it fails, debug initial calibration, movement formula, variable update, or door
    sequence.
  </Module.Phase>

  <Module.Phase kind="ref" label="Reflect · 20 min" title="Safety and state">
    Analyze what would fail if the elevator did not remember the current floor or opened doors while
    moving. Each group presents a state table and one safety improvement. To scale the challenge, 1st
    básico traces floor changes with guidance, 2nd básico debugs the floor-to-floor formula, and 3rd
    básico adds destination validation or operating limits.
  </Module.Phase>
